# 前端与真实联调

先读 PRD、接口、代码和设计，延续已有切片。新 Web 默认 Next.js App Router + TypeScript strict，用语义 CSS 变量统一视觉，Tailwind 按工程采用。已有框架不为模板迁移。

## 一条闭环

列页面、动作、状态：加载/空/成功/失败/校验/提交/恢复。长任务再考虑排队、运行、等待确认、部分成功、取消和断线；短 CRUD 不强加全套 Agent 状态。

页面→业务功能→集中 API 客户端→后端；地址、错误、超时、契约校验集中。TypeScript 类型不验证实际 JSON，边界使用 unknown 与运行时校验。未知枚举不当成功。URL保存定位/筛选，后端保存业务数据，组件保存临时表单，Local Storage只放非敏感偏好。刷新按ID恢复。确有共享复杂度才引入缓存/全局状态库。

表单有Label和限制，错误靠近字段，失败保留输入，提交防重复，后端仍校验。重要删除先说明并确认。成功回读后端，并发编辑提示刷新，不覆盖新值。无真实取消能力时写“停止等待”。确认点展示已有结果、选项/影响和下一步，后端保存确认再推进。

SSE/轮询在终态停止，切任务关闭旧连接；重连先查询，不重复创建。媒体在范围内才验预览/下载/失效与对象释放；语音权限和设备能力需真机验证，模拟尺寸不能冒充真机。

## 视觉和可访问性

遵循用户设计；没有则说明中性方向、做代表页，在授权内继续。默认用系统字体/许可明确资源，避免构建必须联网获取字体。

语义控件、键盘焦点、可读标签、非纯颜色状态、适当 live region。默认检查390/768/1280/1440宽度，核心页面与弹窗无意外横向滚动，操作可触达。设备模拟只是布局证据。

## 联调与构建

实际启动后端，通过页面完成输入→提交→结果→刷新。检查控制台和失败请求；构造空/错误/断网并验证恢复和草稿保留。记录错误注入方式，不冒充真实上游故障。

执行Lint、类型、适用业务测试、生产构建；Next新版不假定 `next lint` 存在，显式使用ESLint。构建后启动生产产物再验代理与静态资源。代理若固化构建时地址需记录，运行时代理则验证读取时点；standalone按实际工程补static/public。

真实后端业务通过才能称联调完成；mock只是原型。Codex观察、自动化检查、用户验收分开记录。
