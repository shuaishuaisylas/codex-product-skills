# 工程适配与后端

## 环境和结构

先读 README、锁文件、入口、测试、当前修改和数据位置。已有项目延续合理技术；新项目给一个推荐，说明采用基线、由 FR 触发的模块、偏离与重评条件。不要让用户承担框架选型。

依赖安装到项目环境，记录解释器、版本锁和启动方式；不修改系统环境迁就旧手册。检查端口，选空闲端口，不结束其他项目服务。优先单体/模块化单体；本地小工具可用标准库 SQLite，多实体/并发/迁移复杂时用 ORM 和迁移。文件索引需 schema 版本、原子写、损坏处理、并发边界，不把业务数据只存内存。

## 接口与状态

每个接口写方法/路径、请求、响应、错误、权限、幂等、超时/重试。新项目默认 `/api/v1`，已有前缀保持兼容。错误如 `{"error":{"code":"INVALID_INPUT","message":"请填写标题"}}`，不泄露堆栈/供应商原文/秘密。

状态转换由后端校验，人工确认点与阶段产物持久化。并发修改可用版本号/事务，有副作用的重复提交用持久化幂等键。超时不证明业务未发生，先查原任务；仅对可安全重试失败有限重试。

长任务按需选提交+查询或 SSE，返回稳定任务 ID，重启能判定恢复/失败/待确认；内存 background task 不等于可靠队列。SSE 含客户端初始化在内的失败统一兜底，以 done/error 收尾。断流先回读任务；取消浏览器等待不等于取消后台任务。

## 数据和权限

- 数据与源码分开；备份恢复到隔离位置并回读，不只看文件存在。
- 多用户按明确业务权限校验对象读写，覆盖越权。共享数据不机械改私有。本地单用户可不加登录，记录访问边界，不称公网生产可用。
- 上传检查大小、内容类型、路径、归属；没有需求不引入 OCR/媒体管线。
- 秘密在后端受控配置；.gitignore 不是打包器保证，检查最终包。日志只留必要 ID/状态/耗时，不含完整文档或凭证。
- 用户/模型内容按不可信内容渲染，HTML默认转义，Markdown限制危险标签/链接。

## 产品需要 AI 运行时才适用

先落实运行时、调用方式、授权/成本/数据边界和验收。用户说用当前 Codex 开发不意味着可把会话嵌入产品；禁止 API 时未接入生成能力保留 NOT_RUN，模拟须标注。

已授权运行时的模型调用集中服务层，Prompt独立管理，模型/超时/预算可配置；确定性校验结构输出，容忍等价格式，内容质量按验收判断，不无限重试。固定流程使用代码状态机；动态Agent限定工具、参数、步数、费用和确认点。

离线测试验证解析/状态/错误；真实运行时验证认证/初始化、输出、延迟、超时/限流和可见产物。没有质量标准就用真实样例帮助明确，不自编准确率。无真实调用证据不能宣称通过。
