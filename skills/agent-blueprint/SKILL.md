# Agent 产品蓝图

仅当用户手动选择本 Skill 或明确调用 `$agent-blueprint` 时使用。普通的 Agent、PRD、架构问题不应触发本 Skill。自动调用由 `agents/openai.yaml` 的 `allow_implicit_invocation: false` 关闭。

用当前 Codex 会话负责需求分析、架构判断、写代码和评审；用原项目的本地程序负责目录、版本、固定选型规则和静态扫描。默认不配置或调用独立模型 API，不搜索其它项目的密钥。

## 准备资料

原项目完整快照封存在 `assets/agent-blueprint-source.zip`，含 MIT LICENSE。来源见 [source.md](references/source.md)。首次使用在用户当前工作目录内选一个独立、尚不存在的引擎目录；用户指定目录时以用户为准。不要在已安装 Skill 内生成产品或安装依赖。

找到 Python 3.10+（macOS 的 `python3` 可能是 3.9，需核对版本），执行：

```sh
"<Python3.10+绝对路径>" "<Skill绝对路径>/scripts/prepare_engine.py" --destination "<用户工作目录>/agent-blueprint-engine"
```

返回路径本身就是引擎根目录。已有引擎先核对来源与文件，不覆盖；为新版本使用新目录。这个模式仅需 Python 标准库，无需 `setup.sh`、`.env` 或联网安装。

读取引擎的 `BLUEPRINT.md` 和 `使用引导.md`；按选型需要读取 [components.md](references/components.md) 指向的组件。原资料中的安装、上线、确认及自动触发描述是待选择的项目方法，不自动扩张用户本次授权。不要一并安装源码内其它 Skills。

## 选择入口

- 点子 / PRD → 方案：需求拆解、五要素建模、规则选型、七层架构、工具和验收。
- 完整产品流程：建立工作区 → 方案 → 代码骨架 → 实际运行与检查 → 后续迭代。
- 已有项目：只读检查，报告缺口与证据；是否修改取决于用户本次要求。
- 新需求：先给 PRD 升版，再重推方案、增量修改骨架、复验。

从用户请求判断入口。缺关键需求时只问影响下一步的问题；可先分析已有材料。未知事实保留“待确认”，可逆实现选择写明默认假设。用户已授权完整构建时，持续完成到可运行结果；不要照抄原 builder 的通用“必须再次确认方案”来打断已授权工作。

具体命令、文件格式及恢复方式见 [workflow.md](references/workflow.md)。

## 完整产品循环

1. **建立工作区。** 在引擎根目录运行 `python -m blueprint init "产品名" "点子或PRD文件绝对路径"`，不加 `--plan`。所有产品材料放进 `out/<实际生成目录名>/`，产品代码仅放该工作区 `skeleton/`。保留原始需求、PRD 版本和用户修改。
2. **需求与选型。** 用当前会话提取用户、目标、输入到交付物的闭环、边界与成功标准，映射工具 / 知识 / 观察 / 行动 / 权限。按原引擎特征表生成 `features.codex.vN.json`，使用 `scripts/local_tools.py select` 执行固定规则并写 `selection.codex.vN.json`。有证据才判 yes/no/later，没有说明判 unknown；别把缺失说成明确不需要。
3. **方案。** 写 `方案.md`：待确认与假设、需求、五要素、17 项选型理由、七层架构、工具输入输出/副作用/权限、提示词草案、失败处理、验收。显式标注“当前 Codex 按项目手册分析，未运行独立模型管线”。不要伪造原管线的 `plan.json`、stages、token 用量或独立模型审稿结果。
4. **构建。** 按业务最小闭环在 `skeleton/` 写可运行代码、启动说明、依赖与配置示例。先读 [limitations.md](references/limitations.md) 的脚手架缺陷；不要把 `init_agent.py` 当成无条件可用的生产模板，不要对已有骨架重新运行生成器。复制参考机制前检查权限、路径、外部动作与适用性。
5. **检查与实跑。** 对 `skeleton/` 运行 `local_tools.py scan`，由当前会话对照 PRD 查源码，写 `差距报告.codex.md`；运行能证明业务闭环及关键失败路径的检查，记录真实结果。静态信号覆盖率不能替代功能测试；无外部模型 / 服务时说明未验证范围。人工验收栏留给用户，AI 实测另记一栏。
6. **迭代。** 新需求先运行 `python -m blueprint revise "工作区绝对路径" "新需求" --no-plan`。读取新 PRD 第 7 节，把需求消化进各节，重做当前会话选型和方案，记录前后变化，增量改代码，再复验。保留 `prd/VN.md` 快照与用户修改；完成后清理已消化的第 7 节内容并标注对应版本“已消化”。

当前 Codex 自查不称为独立模型审稿；另一个子 Agent 的审查可据实称为另一次会话内审查。引擎参考实现、生成骨架、真实工具验证和生产验收是不同证据。

## 交付

给出已完成步骤、运行证据、未通过或未验证项、关键文件绝对路径和下一步。结果状态依据真实证据，可写“可运行骨架”“静态检查完成”“待业务验收”；不因目录齐全、程序退出或原文自称 production 就声称已上线或生产可用。
